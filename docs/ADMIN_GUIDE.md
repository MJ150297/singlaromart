## 1. Access and permissions

1. Open `/admin/login`.
2. Enter the owner email and password.
3. After authentication, the panel opens at `/admin/dashboard`.

When setup has not been completed, the first account can be created at `/admin/signup`; that account becomes the owner. Signup is unavailable after an owner exists. Admin mutations are owner-protected, so a hidden menu item is not a security boundary.

Use the account area at the bottom of the sidebar to open Settings or log out. A successful password change signs the owner out and requires a new login.

## 3. Daily operating workflow

1. Create or verify categories and subcategories.
2. Add products and assign the correct taxonomy.
3. Upload images and verify price, stock, and Published status.
4. Create or update banners.
5. Create an offer carousel when a product group needs homepage placement.
6. Configure delivery fees and promotions after base catalog data is correct.
7. Place a test storefront order and verify product, pricing, delivery fee, and status flow.

## 4. Catalog management

### Categories and subcategories

Open **Categories → Add Category**. The category form contains:

| Field | Required | Notes |
|---|---:|---|
| Name | Yes | Customer-facing category name |
| Icon (emoji) | No | Optional navigation/card icon |
| Slug | No | URL-friendly value; can be generated by the server |
| Sort Order | No | Lower values appear first; default `0` |
| Description | No | Short category description |
| Category Image | No | Upload or paste a direct URL |
| Active | No | Deactivate to hide without deleting |

Select **Add Subcategory** for each child grouping. Each row supports name, optional slug, and optional image. Empty rows are ignored when saving. Save the category, then verify its active state, sort order, and subcategory count. Use search, status filters, sorting, pagination, CSV export, and bulk actions on the list. Reassign products before deleting a category.

### Products

Open **Products → Add Product**. Required fields are **Name**, **Category**, **Unit**, **Price**, and the primary **Image**. The full, step-by-step process is in [Admin Catalog Operations](./ADMIN_CATALOG_OPERATIONS.md).

The form supports:

- Identity: name, slug, category, unit.
- Pricing: selling price, optional original price, and discount percentage from `0` to `100`.
- Inventory: stock quantity and **In Stock**.
- Visibility: **Published**; only published products appear in normal storefront and offer results.
- Images: primary, additional, and optional variant images through Cloudinary or URLs.
- Details: description, origin, storage info, health fact, badges, tags, and nutritional info (one item per line).
- Variants: unit, price, optional original price/discount, stock toggle, and image.
- Subcategories: one or more subcategories belonging to the selected category.

Use filters for category, stock, published state, price range, search, sort, and pagination. The list supports CSV export, refresh, bulk publishing/unpublishing, and deletion. Check manual offers before deleting a product.

### Product publishing checklist

Verify category, unit, prices, stock quantity, **In Stock**, primary image, variant data, tags/badges, and **Published** before release. Saving a product and publishing it are separate actions.

## 5. Homepage content

### Banners

Open **Banners → Add Banner**. Enter a title, then optionally subtitle, badge, CTA text, gradient, image, and display order. Enable **Active** to show it. The page supports edit, toggle, reorder, duplicate, delete, export, bulk actions, and preview.

### Offers

Open **Offers → Add Offer**. Enter name, optional slug/description, and sort order. Choose exactly one selection type:

- **By Tag**: all published products carrying the entered tag.
- **By Category**: all published products in the selected category.
- **Manual**: exact products selected through search and category filters; selection order is retained.

Optionally add a banner image, start date, and end date. Leave dates empty for no schedule boundary. An offer is visible only when active and inside its schedule. Use **Preview** before saving; row actions support activate/deactivate, duplicate, edit, and delete.

Changing selection type changes the source of truth; tag, category, and manual selections are not combined. Tag/category offers update as published products change. Manual offers skip missing or unpublished products.

## 6. Orders

Use **Orders** to search, filter, and open order details. Review customer, address, items, quantities, pricing, payment, and promotion snapshot before changing status.

Normal status path: `Pending → Confirmed → Out for delivery → Delivered`. Update status only after the operational event occurs. Cancellation and refund actions may affect coupon redemptions, credits, and referral rewards.

## 7. Promotions and money movement

Checkout is server-authoritative: it recalculates prices and stores an immutable order pricing snapshot. See [Promotions](./PROMOTIONS.md) for the frozen policy.

- **Delivery Fees**: maintain global, category, subcategory, product, and optional slot-specific rules. Precedence is free-delivery coupon, product, subcategory, category, global.
- **Coupons**: manage codes, dates, limits, minimum order, scope, first-order restrictions, caps, and active state. Current policy allows one coupon per order.
- **Referral programs**: configure referred-user benefit, referrer reward, and expiry.
- **Credits**: inspect balances and record manual adjustments with a reason.
- **Refunds**: process promotion reversals so coupon usage and consumed credits are restored correctly.
- **Reports**: inspect promotion performance and export CSV.
- **Audit**: review coupon, referral, delivery-rule, credit, refund, and promotion activity.

Lifecycle rules: coupon redemption is reserved at order creation, redeemed on delivery, and released on cancellation/refund. Store-credit consumption is recorded in an append-only ledger; refunds create a new restoration entry. Used coupons, redemptions, ledger entries, and audit events are not hard-deleted.

## 8. Account settings

Settings can update owner name and email. Phone and role are read-only. Password changes require the current password, a new password of at least eight characters, and confirmation; successful changes sign the owner out.

## 9. Data and storefront rules

- Prices are tax-inclusive INR amounts.
- Only published products are returned to normal storefront and offer results.
- `In Stock` and stock quantity are separate controls.
- Category and offer active flags are visibility controls; deactivate when history or reuse matters.
- Offer visibility depends on active state and start/end datetime.
- Images may be Cloudinary objects or direct URLs; confirm the preview before saving.
- Product tags drive tag-based offers, so keep spelling consistent.

## 10. Troubleshooting

| Symptom | Check |
|---|---|
| Product does not appear | Published, In Stock, category, valid image, price, and stock. |
| Offer is empty | Active state, schedule, published products, exact tag/category, or manual selections. |
| Subcategories are missing | Select the parent category and confirm its subcategories were saved. |
| Coupon total is unexpected | One-coupon rule, minimum, cap, scope, expiry, delivery fee, referral discount, and credits. |
| Delivery fee is unexpected | Rule scope/slot precedence and free-delivery override. |
| Image does not load | Re-upload or replace the URL, save, and refresh. |
| Changes are not visible | Refresh the admin list and check active/published filters and schedule. |
